# portscan

Независимый Go-пакет для TCP Connect-сканирования. Go **1.25.5**, только стандартная библиотека. Не использует SYN, UDP, raw sockets; не определяет сервисы или ОС.

## Использование

Путь модуля `example.com/portscan` — локальный демонстрационный путь. Перед публикацией замените его в `go.mod` и импортах на адрес своего репозитория.

```go
scanner, err := portscan.New(
    portscan.WithConcurrency(100),
    portscan.WithConnectTimeout(500*time.Millisecond),
)
if err != nil {
    return err
}
ctx, cancel := context.WithCancel(context.Background())
defer cancel() // Обязательно, если прекратите читать results раньше закрытия.
results, err := scanner.Scan(ctx,
    []string{"127.0.0.1", "::1", "localhost"},
    portscan.Union(portscan.List(22, 80, 443), portscan.Range(8000, 8010)),
)
if err != nil {
    return err
}
for result := range results {
    fmt.Printf("%s %s:%d %s: %v\n",
        result.Host, result.IP, result.Port, result.State, result.Err)
}
return scanner.Shutdown(context.Background())
```

Рабочий пример с SIGINT/SIGTERM: `go run ./examples/graceful`.

## Публичный API

- `New(...Option) (*Scanner, error)` — создание сканера. Значения по умолчанию: 100 сетевых операций, 1 секунда на подключение или DNS-запрос.
- `WithConcurrency(int)` — положительный общий лимит одновременных сетевых операций **для экземпляра**, в том числе при параллельных вызовах `Scan`. DNS-запрос тоже занимает слот.
- `WithConnectTimeout(time.Duration)` — положительный таймаут каждой попытки подключения и каждого DNS-запроса. DNS и подключение имеют отдельные бюджеты; контекст сканирования ограничивает весь запуск.
- `List(...int)`, `Range(first, last int)`, `Union(...Ports)` — неизменяемые наборы портов. Диапазоны включают обе границы. Ошибки наборов возвращаются из `Scan` до запуска фоновых операций.
- `Scan(context.Context, []string, Ports) (<-chan Result, error)` — валидация и асинхронное сканирование. Ошибка возврата относится к входным данным или жизненному циклу, сетевые ошибки находятся в `Result.Err`.
- `Shutdown(context.Context) error` — окончательное завершение экземпляра, подробнее ниже.
- `ErrShutdown` — ошибка нового сканирования после начала shutdown, проверяется через `errors.Is`.

`Result` содержит `Host string`, `IP netip.Addr`, `Port uint16`, `State State`, `Duration time.Duration`, `Err error`. `netip.Addr` выбран как неизменяемый тип значения, безопасный для передачи между горутинами. `Duration` — время подключения без очередей; при ошибке DNS — длительность DNS-запроса. Соединение закрывается сразу после попытки подключения. Ошибка закрытия не меняет результат успешного TCP handshake.

## Правила обработки целей и портов

| Вход | Поведение |
| --- | --- |
| IPv4, IPv6 | Прямое подключение без DNS; IPv6 без квадратных скобок, zone ID поддерживается |
| DNS | ASCII hostname, допускается punycode; регистр и конечная точка нормализуются |
| DNS с несколькими IP | Каждая уникальная пара IP/порт проверяется; IPv4-mapped IPv6 нормализуется в IPv4 |
| Неразрешимый DNS / пустой ответ | `error` для каждого порта, невалидный `IP`; исходная DNS-ошибка доступна через `errors.As` |
| Таймаут DNS | `timeout` для каждого порта |
| Дубликаты хостов | Удаляются после нормализации; разные DNS-имена с одинаковым IP остаются отдельными целями |
| Пустой список / пустой хост / пробелы / URL / host:port / CIDR / некорректный IP | Синхронная ошибка `Scan` |
| Числовое DNS-имя | Отклоняется, чтобы некорректный IPv4 не интерпретировался как DNS |
| Порт ≤ 0 / > 65535 / обратный диапазон / пустой набор | Синхронная ошибка `Scan` |
| Дубликаты портов | Удаляются, сохраняется первое вхождение |

DNS выполняется один раз на имя в рамках запуска. DNS неудачи не мешают остальным хостам. Порядок результатов не гарантирован. Без отмены возвращается ровно один результат на уникальную тройку host/IP/port; при неудаче DNS — один на host/port.

## Состояния

| State | Условие |
| --- | --- |
| `open` | TCP handshake успешен |
| `closed` | `ECONNREFUSED` |
| `timeout` | Истёк таймаут отдельной операции или `net.Error.Timeout()` |
| `unreachable` | `ENETUNREACH`, `EHOSTUNREACH`, `ENETDOWN`, `EHOSTDOWN` |
| `canceled` | Активная попытка отменена контекстом сканирования или принудительным shutdown |
| `error` | Прочие ошибки, включая DNS not found и permission denied |

Классификация использует `errors.Is` / `errors.As`, без сравнения строк. Недоступность сети может проявляться как таймаут: пакет сообщает наблюдаемый результат ОС, не предполагаемую причину.

## Конкурентность, отмена и backpressure

На запуск создаётся ограниченный пул воркеров и производитель заданий. Декартово произведение целей и портов не хранится в памяти. Буфер результатов равен concurrency. Медленное чтение замедляет выдачу новых заданий, но не держит TCP-соединения открытыми. При множестве одновременных запусков число воркеров и буферов растёт пропорционально числу запусков; сетевой лимит остаётся общим.

После отмены новые операции не запускаются при следующей проверке контекста, выполняющиеся `DialContext` и DNS получают отмену. В гонке с отменой уже выбранное задание может попасть воркеру, который проверяет контекст перед сетевой операцией. Канал закрывается после завершения производителя и всех воркеров. Ожидающие отправки не мешают отмене.

**Отмена — частичный результат:** не начатые проверки не получают синтетических результатов, а результаты завершённых или отменённых операций могут быть отброшены, чтобы остановка не зависела от читателя. Поэтому `canceled` может присутствовать, но не гарантирован для каждой прерванной попытки. После закрытия канала проверяйте `ctx.Err()`; при принудительном shutdown его инициатор получает ошибку `Shutdown`. Если нужна полная выдача, читайте канал до закрытия без отмены.

Входные хосты копируются до возврата `Scan`; `Ports` не раскрывает изменяемые срезы. Экземпляр можно использовать повторно и конкурентно до shutdown; копировать `Scanner` и использовать его нулевое значение нельзя. Пакет не устанавливает обработчики сигналов, не пишет логи и не содержит глобального изменяемого состояния (кроме стандартной экспортируемой sentinel-ошибки).

## Graceful shutdown

1. Приложение получает SIGINT/SIGTERM и вызывает `Shutdown` с отдельным grace-контекстом.
2. Новые `Scan` возвращают `ErrShutdown`.
3. Принятые сканирования продолжаются, приложение продолжает читать результаты.
4. Если они завершились в срок, `Shutdown` возвращает `nil`.
5. Если grace-контекст отменён или истёк, сканирования отменяются, `Shutdown` возвращает ошибку этого контекста. Повторный `Shutdown` позволяет дождаться закрытия каналов и окончания воркеров.

Shutdown идемпотентен и безопасен при конкурентных вызовах. Истечение контекста любого вызова принудительно отменяет все запуски. После shutdown экземпляр не перезапускается. Для мягкого завершения не передавайте signal-контекст самому `Scan`: это немедленно отменит работу вместо ожидания grace-периода. См. `examples/graceful/main.go`.

## Проверка

```sh
go version                    # go1.25.5
go test -race ./...
go vet ./...
go build ./...
# либо make check
```

Для выбора точной версии при установленном другом Go: `GOTOOLCHAIN=go1.25.5 go test -race ./...`.

Тесты используют локальные TCP listeners и управляемые внутренние сетевые функции: IPv4/IPv6, закрытие соединений, ошибки DNS, несколько IP, таймауты, глобальный лимит, отмена большого диапазона, брошенный читатель, завершение текущих операций и гонка Scan/Shutdown. Внешняя сеть тестам не нужна; IPv6-тест пропускается, если IPv6 недоступен. CI запускает проверки на Go 1.25.5.
